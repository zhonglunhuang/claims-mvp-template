# 種子資料（虛構的測試資料）

這裡放開發與 Staging 用的測試資料。模板本身沒有種子檔，Day 10 的 T1 會建立。

## 規則

- 檔名：`NN_名稱.sql`，兩位數字決定執行順序，例如 `01_departments_users.sql`、`02_claims.sql`。
- 可以重複執行：用 `INSERT … ON CONFLICT DO NOTHING` 這類寫法，重跑不會多出重複的資料。
- 只放虛構的資料，不放真實的姓名、Email 或任何密碼。登入用測試帳號快速登入，不需要密碼。
- 六個測試帳號照 `docs/test-accounts.md` 的順序建立，id 才會是 1 到 6。
- 種子資料要符合目前的規則（例如狀態不是草稿的單，要有一致的審核紀錄）。

## 怎麼執行

```bash
npm run db:seed
```

- 全部檔案放在同一個交易：任何一個失敗，全部還原，不會只放一半。
- 每個檔案印一行 `[seed] 01_departments_users……完成`。
- 部署時用 `--if-empty`：資料庫還沒有任何帳號才放，已經有帳號就略過。
